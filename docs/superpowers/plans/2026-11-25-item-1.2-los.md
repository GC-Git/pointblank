# Item 1.2: Line of sight (3D on a 2D map) — plan

**Goal:** a deterministic, symmetric, graded line-of-sight query over `GameMap`, with eye
height by posture and floor, and blocking or partial blocking by hedges, woods, elevation and
buildings. Code in `src/Sim/Sight/`, tests in `tests/Sim.Tests/Sight/`.

## API

- `Posture { Standing, Kneeling, Prone }`.
- `Viewpoint(Fixed X, Fixed Y, Posture Posture, int Floor = 0)`: a position in metres from
  the map's north-west corner (x east, y south) and a floor (0 = ground). `Floor > 0` needs a
  building on that tile with more floors than `Floor`.
- `LosResult(bool Visible, Fixed Obscurement, LosBlocker Blocker, TilePos BlockerTile)`.
  `Obscurement` is 0..1 (capped), accumulated from woods and hedges; spotting (item 1.6) uses
  it and adds the target's own concealment separately. `Blocker` is `None`, `Ground`,
  `Hedge`, `Woods` or `Building`.
- `SightRules` (record; `FromData(DataSet)`): eye heights, floor height, block threshold,
  hedge height and obscurement, per-terrain canopy height and obscurement per metre. Tests
  can vary it with `with`.
- `LineOfSight(GameMap, SightRules)`: `EyeHeight(Viewpoint)`, `Check(a, b)`,
  debug helpers `Trace(a, b)` (one `LosStep` per tile visited) and
  `VisibleTiles(observer, targetPosture)` (a per-tile grid for the item 2.6 overlay).
  It snapshots the map's per-tile arrays when built; build a new one after the map changes.

## Data (all placeholders, sourced-value format)

- New table `postures`: `standing`, `kneeling`, `prone`, each `eye_height` (1.6, 1.0, 0.3 m).
- New table `sight`, entry `default`: `floor_height` 3 m, `block_threshold` 1.
- `terrain` gains `los_obscurement`: open 0, road 0, light woods 0.04 per metre (25 m of
  woods blocks), hedge 1 per crossing (a hedge is opaque below its top).
- `terrain/hedge/block_height` changes from 2 m to 1.4 m (still a placeholder), so a
  standing man sees over a hedge and a kneeling or prone one does not. (A 2 m hedge would
  hide a standing man too, contradicting "a standing soldier is seen".)

## Rules

1. **Eye height** = ground of the viewpoint's tile + `Floor × floor_height` + posture eye
   height. Target and observer use the same formula: we test the ray between the two eyes.
2. **Symmetry**: the trace always runs from the endpoint that is smaller by
   (x, y, eye height) to the other, so `Check(a, b) == Check(b, a)` bit for bit.
3. **Traversal**: exact grid walk (Amanatides–Woo order). The next crossing (vertical vs
   horizontal grid line) is chosen by comparing `numX·|dy|` with `numY·|dx|` in `Int128`
   on raw values, so it is exact; crossing parameters `t` are computed from the start each
   time (no accumulated error), only for heights. Step counts are fixed by the tile
   difference, so the walk always ends in the target tile.
4. **Corner crossings** (the ray passes exactly through a tile corner): both L-shaped paths
   are evaluated (edge crossings only; the corner tile has zero length) and the less obscured
   unblocked one is used (if both block, the x-first path's blocker is reported). So a
   continuous hedge line never leaks, and a hedge or wall that merely ends at the corner
   does not block.
5. **Ground**: elevation is a flat-topped step per tile (the tile-centre value). For every
   tile except the two endpoint tiles, the ray is blocked by `Ground` if its height entering
   or leaving the tile is below that tile's ground. A crest of higher tiles between two
   soldiers therefore blocks.
6. **Woods**: in a tile whose terrain has `los_obscurement > 0`, if the ray is below
   ground + canopy (`block_height`) at entry or exit, obscurement += per-metre value × the
   horizontal length of the ray in the tile. Endpoint tiles count (being in woods obscures).
   Building tiles ignore terrain.
7. **Hedges**: a thin wall on the tile edge, top = max(ground of the two tiles) + hedge
   height. A ray crossing the edge below the top adds the hedge obscurement (1 now, so it
   blocks). **Adjacent rule: there is none** — a soldier touching a hedge is treated like
   any other: a standing soldier (1.6 m) sees over a 1.4 m hedge, a kneeling or prone one
   does not see through it, even to a soldier touching the far side. Peeking through
   bocage firing gaps is left to later items.
8. **Buildings** (minimal; item 4.4 refines): roof = building tile ground + floors ×
   floor height. A building that contains neither endpoint blocks any ray passing a tile of
   it below the roof. A building that contains an endpoint is open inside (no interior
   walls); the ray may leave or enter it only through a door or window on the crossed
   tile side, on the floor at the ray's height (`(h - ground) / floor_height`, clamped), or
   above the roof. Seeing in one window and out another of a third building is blocked.
9. **Threshold**: when accumulated obscurement reaches `block_threshold`, the ray is
   blocked by whatever pushed it over (`Woods` or `Hedge`).

## Performance budget and scheduling

300 soldiers → 300 × 300 = 90,000 ordered pairs. Scheduling (for items 1.6/1.7): LOS for a
pair is refreshed on a stagger, each pair once every 10 ticks (1 s of game time); the
check is symmetric, so unordered cross-side pairs (150 × 150 = 22,500) suffice in
practice. The test runs the full 90,000 checks between seeded random positions on the
300 m test map (worst case: every ordered pair, every soldier, in one batch).

Budget: the full 90,000 batch completes in **1 s in a Debug test build** (`dotnet test`
default). Staggered over 10 ticks that is at most 100 ms of CPU per second of game time
(10 ms per 100 ms tick, 10 % of one core) at the worst case, and about 2.5 % for the
realistic 22,500 unordered cross-side pairs; a Release build is about four times faster.
To stay robust on a slower or busy machine, the test takes the best of three runs and
allows **3 × the budget** (3 s); it also checks that the batch's results hash the same on
every run.

Measured on the dev machine: Debug 825 ms, Release 195 ms (about 2 µs per check). The first
version divided (Int128) at every crossing and took 1.56 s in Debug; the walk now steps the
exact cross products and the ray parameter and height by constants (additions only).

## Tests (written first)

- Prone behind hedge at 100 m, flat ground: not visible, blocker `Hedge`; standing: visible.
- 2nd-floor observer at a window sees a kneeling target beyond a hedge; the same observer on
  the ground floor (window there too) does not.
- A crest of raised tiles blocks two standing soldiers (`Ground`); flat ground does not.
- Woods: obscurement grows with woods length and blocks beyond the threshold.
- Partial hedge (rules `with` hedge obscurement 0.5): visible with obscurement 0.5.
- Building: a closed building between soldiers blocks; an observer inside sees out through
  a window but not through a wall.
- Corner: a ray exactly through a corner with a continuous hedge line is blocked; with a
  hedge ending at the corner it is not.
- Symmetry: `Check(a, b) == Check(b, a)` on many random pairs on the test map.
- Eye height by posture and floor; viewpoint validation.
- Data: the new tables load; terrain values read.
- Performance as above.
