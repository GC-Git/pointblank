# Item 1.1 Map model: plan

Code in `src/Sim/Map`, tests in `tests/Sim.Tests/Map`, data in `data/terrain.json`, test map in
`data/maps/test_300.map.json`.

## Design

- **Tiles:** 2 m. The size is stored per map (`tile_size_mm`, default 2000) and exposed as
  `GameMap.TileSize` (`Fixed`, metres). Nothing else hard-codes it. Test map: 150 x 150 tiles.
- **Terrain types (tile property):** `Open`, `Road`, `LightWoods`. Per-type cover, concealment,
  movement cost (walk, fast, sneak) and block height come from `data/terrain.json` (all
  `placeholder`), read through a typed `TerrainTable`. The loader gains a `terrain` table and the
  typed fields it needs.
- **Hedges are tile-edge features, not a tile type.** Bocage is a linear barrier between fields: a
  tile type would force a hedge to be 2 m thick and fill a whole tile (units could stand "in" it),
  and LOS (item 1.2) would need to treat a blocked tile differently from a blocked edge. As an edge
  feature (`East` and `South` edge of a tile, so each edge has one owner) LOS tests a ray crossing
  a tile boundary against the edge's block height, and movement pays the crossing cost. Hedge
  properties are the `hedge` row of `terrain.json`.
- **Elevation:** integer decimetres at the tile centre, stored as such (exact round trip), returned
  as `Fixed` metres. 1.2 can interpolate between centres.
- **Buildings:** id, floors 1-3, wall material id (checked against `materials.json` ids when a set
  is passed to the loader), footprint (set of tiles, canonical order), openings (door or window on
  a tile edge of the footprint, with floor). Footprint may not overlap another building.
- **File format:** JSON, version 1. Terrain is row strings (`.` open, `=` road, `w` woods).
  Elevation is one space-separated row string per row. Hedges are a sorted list. Building
  footprints are row runs `[x, y, length]`. Saving is canonical, so a resave is byte-identical.
- **Hash:** `GameMap.ComputeContentHash()` (FNV-1a via `StateHasher`). `MapSystem : ISimSystem`
  puts the map into `World`'s state hash. The replay record is unchanged (map id + version); the
  hash covers divergence. Recording the content hash in the replay file is a follow-up.
