# Item 0.1 Repo, Rules and Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buildable, testable, headless-runnable skeleton with the project's rules and process prompts in place.

**Architecture:** `src/Sim` is a plain C# class library with no Godot references. `tests/Sim.Tests` tests it with `dotnet test`. `game/` is a Godot 4.7 .NET project that references `Sim` and shares the root solution `PointBlank.sln`.

**Tech Stack:** .NET SDK 9 building `net8.0` (Godot.NET.Sdk 4.7.0's default), xUnit, Godot 4.7 mono.

**Spec:** `docs/superpowers/specs/2026-11-25-pointblank-vision-design.md`, checklist `docs/checklist.md` item 0.1.

## Global Constraints

- `Sim`: no Godot references.
- No historical number is hard-coded; every data value has a source tag (`source`, `estimated` with reasoning, or `placeholder`).
- One checklist item per session/branch/PR. Never push to `main`, never merge.
- Godot: `C:\Godot_v4.7-stable_mono_win64\Godot_v4.7-stable_mono_win64_console.exe`.
- `.mcp.json` is not modified.
- Do not tick the checklist box (ticked only when the PR is merged).

## Review Focus

- Fresh clone with no `game/.godot`: the headless Godot build must work on first run (Task 2, step 4).
- Plain `git push` while on `main`: pattern rules cannot see the branch; document it and recommend GitHub branch protection (Task 3).
- Reworded push/delete commands (`git -C . push`, force flags after the remote, other drive letters): deny samples must cover them (Task 3, step 2).
- Godot rewriting `project.godot` or adding files on open: `git status` clean apart from intended files after the headless run (Task 4).
- CRLF checkout on Windows: listed text types are LF in the working tree (Task 1, step 3).
